# PRD: 面談一覧のページング

対象画面は組織内の面談一覧（`/planning/meetings`）だけとする。ペア一覧は対象外。

## 背景

面談一覧は `GET /api/v1/meetings/all` が権限内の面談を全件返し、絞り込みと並び替えを画面側で全件に対して行っている。件数が多いときに、表示に必要な分だけを取り、隣のページは先に用意しておきたい。

## ゴール

- 一覧はページ単位で取得し、画面にはそのページの行だけを出す。
- 開いたページはすぐ表示し、その前後のページを裏で取得する。
- 並び替えは実施日の昇順・降順のみ。サーバがページを切る前に並べる。
- メンター、メンティ、部署、状態、実施日の範囲は、ページを切る前にサーバで絞り込む。

## ページの取り方

1ページの件数は 20 件。ページ番号は 1 から始まる。

画面が保持するのは、表示中のページと、その直前・直後のページだけである。

| 操作 | 画面 | 取得するページ |
| --- | --- | --- |
| 初期表示 | 1ページ目 | 1 と 2 |
| 2ページ目を開く | キャッシュにあれば 2 ページ目をすぐ表示 | 裏で 1 と 3 |
| 3ページ目を開く | キャッシュにあれば 3 ページ目をすぐ表示 | 裏で 2 と 4 |

- 表示しようとしたページが未取得のときは、そのページの取得が終わってから表示する。その後に前後を取る。
- 前後を取るとき、1 より小さいページと、最終ページより大きいページは取らない。
- 窓の外のページは捨てる。表示が 3 ページ目なら 1 ページ目は持たない。
- キャッシュ済みの前後は、ページを開くたびに取り直す。
- 絞り込み、実施日の昇降順の変更、ページ移動のいずれでも、最後に要求した条件・ページ番号と一致する応答だけを表示に使う。遅れて届いた古い応答は捨てる。
- 絞り込み、または実施日の昇降順が変わったら、キャッシュを捨てて 1 ページ目に戻し、1 と 2 を取り直す。

## 並び替え

- 実施日の列を押すと `dir` を `asc` と `desc` で反転し、サーバから取り直す。初期値は `desc`（実施日が新しい順）。
- 実施日が未設定の面談は、並びでは最も古いものとして扱う。実施日の範囲フィルタ（から / まで）があるときは除外する。
- 実施日が同じ面談は、メンター名の昇順、同じならメンティ名の昇順（日本語ロケール）。`dir` が `asc` でも `desc` でも名前の方向は昇順のまま。
- 実施日と両方の名前も同じ面談は、サーバ内部の ID 降順で安定させる。ID は応答にも画面にも出さない。
- 部署、メンター、メンティ、テンプレート、状態の列見出しは表示のみ（並び替えボタンなし）。部署列はメンター側とメンティ側の 2 列のまま。

## 絞り込み

次の条件はサーバがページを切る前に適用する。画面のフィルタはそのまま使い、条件が変わるたびに 1 ページ目から取り直す。同一項目の複数指定は OR、項目間は AND。

- メンター（複数）。ペアのメンター UUID が一致
- メンティ（複数）。ペアのメンティ UUID が一致
- 部署（複数）。メンターまたはメンティのいずれかが、選ばれた部署のいずれかに所属していれば残す（所属は DB 上の部署メンバー全件で判定）
- 状態（`1` 未着手 / `2` 下書き / `3` 完了）。空はすべて。`4` などそれ以外は 400
- 実施日（から / まで）。日付は `YYYY-MM-DD`。から はその日の始まり（JST）以降、まで はその日の終わり（JST）以前。`from` が `to` より後のときは 200 で 0 件

部署名の表示は、今どおりディレクトリの所属名を画面で引く。

## API

`GET /api/v1/meetings/all`

クエリ:

- `page` : 既定 1。1 未満または整数でないときは 400
- `pageSize` : 20。これ以外を指定しても 20 として扱う
- `dir` : `asc` または `desc`。既定 `desc`。それ以外は 400
- `mentorUuids` : カンマ区切りのユーザー UUID。不正な形式は 400
- `menteeUuids` : カンマ区切りのユーザー UUID。不正な形式は 400
- `departmentUuids` : カンマ区切りの部署 UUID。不正な形式は 400。存在しない UUID は一致なし（0 件になり得る）
- `status` : `1` / `2` / `3`。空はすべて。それ以外は 400
- `from` / `to` : `YYYY-MM-DD`。不正な形式は 400

応答:

```json
{
  "items": [],
  "total": 123,
  "page": 2,
  "pageSize": 20
}
```

`items` はその条件・並びでの 1 ページ分。`total` は絞り込み後の件数。指定ページが最終ページより大きいときは `items` は空、`total` は正しい件数、`page` は要求された番号のまま。

見える面談の範囲は今の権限判定と同じとする（内部の `ListPlanningMeetings` は全件のまま）。HTTP 応答だけ、取得後に絞り込み・並び・スライスを行い 1 ページ分を返す。`POST /api/v1/meetings/all` は変えない。

## 画面

- 表の本体は表示中ページの行だけ。受け取った並びをそのまま表示する（画面側のソートなし）。
- 0 件のときは「該当する面談がありません」。ページャは出さない。
- 1 件以上のとき、表の下に前へ、ページ番号、次へ、総件数を出す。ページ数が多いときは先頭・末尾・現在の前後のみ番号を表示する。

## 対象外

- ペア一覧のページング
- 列ごとのクライアント並び替え
- データベースの `LIMIT` による取得への置き換え
